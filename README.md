# braid

Claude 的多帳號工具。每個帳號是一股線，你的工作是編成的那一條辮子：
換帳號時把一股接進另一股（**遷移**），用量用完換另一股承重（**用量切換**），
幾個帳號長期並用就把它們編在一起（**同步**）。

| 用法 | 給誰 | 狀態 |
|---|---|---|
| 遷移 | 換帳號，搬一次就好 | **可用**（桌面 app） |
| 用量切換 | 一個帳號用量快用完時，提醒你換成哪個帳號（你自己在桌面 app 換或 `/login`，braid 不替你換） | **可用**（CLI 與桌面 app 的對話；Windows、macOS、Linux） |
| 同步 | 桌面 app 的兩個帳號長期並用：對話自動同步，用量用完換過去就能接著做 | **可用**（桌面 app） |
| 歸屬 | 公司與個人分開：依資料夾決定新頁（artifact）用哪個帳號發布，對話不受影響 | **試用中** |

裝好後在 Claude Code 輸入 `/braid` 打開面板。第一次會問你要用哪幾種，沒選的不會出現。

## 安裝

三種方式擇一，都不用改任何設定檔。

**A. 請 Claude 幫你裝**：在任何一個 Claude Code 對話（桌面 app 的 Code 分頁也可以）輸入：

> 請照 https://github.com/MiskaWu/braid README 的「給 Claude 的安裝步驟」幫我安裝

**B. 自己在終端機裝**（電腦上有 `claude` 指令的話）：

```bash
claude plugin marketplace add MiskaWu/braid && claude plugin install braid@braid
```

**C. 只要遷移、不裝**（不需要 Claude Code）：下載這個 repo，Windows 雙擊 `mod/tool/windows/migrate.cmd`，
macOS 雙擊 `mod/tool/macos/migrate.command`（從瀏覽器下載的話，第一次要按右鍵 →「打開」）。

### 更新

建議打開自動更新（第三方 marketplace 預設關著，只能每個人自己開）：在 Claude Code 輸入 `/plugin` →
**Marketplaces** → **braid** → **Enable auto-update**。之後開新對話時會在背景檢查，有新版會提示你輸入 `/reload-plugins`
（不輸入的話，下次開 Claude Code 就是新版）。

沒打開也沒關係：braid 會自己查 GitHub 上的版本（最多 12 小時一次），有新版時面板上方出現
「更新並重新載入」，按一下就幫你更新並重新載入。也可以自己在終端機執行：

```bash
claude plugin marketplace update braid && claude plugin update braid@braid
```

### 給 Claude 的安裝步驟

照下面做，不要改 `settings.json`，也不要替使用者執行遷移或新增帳號（這些由使用者自己在面板操作）。

1. 決定用哪個 `claude`：`command -v claude` 有結果就用它；沒有的話用環境變數 `$CLAUDE_CODE_EXECPATH`
   （目前這個 Claude Code 本身，桌面 app 的 Code 分頁裡也有）。以下記作 `$CLAUDE`。
2. 加入 marketplace：`"$CLAUDE" plugin marketplace add MiskaWu/braid`。
   已經加過的話改跑 `"$CLAUDE" plugin marketplace update braid`。
3. 安裝：`"$CLAUDE" plugin install braid@braid`。已經裝過的話改跑 `"$CLAUDE" plugin update braid@braid`。
4. 用 `"$CLAUDE" plugin list` 確認 `braid@braid` 是 enabled，然後告訴使用者：先輸入 `/reload-plugins`
   （或開一個新對話），再輸入 `/braid` 打開面板。

## 面板

`/braid` 打開面板，分頁依你選的用法出現；按「用法」可以改。也可以直接開到某一頁：`/braid 帳號`、`/braid 切換`、`/braid 同步`、`/braid 歸屬`。

- **帳號**：這台電腦認得的帳號、各自的用量（目前帳號即時，其他帳號是上次用它時的數字）。
  每張卡會說怎麼換成它：桌面 app 的對話在 app 裡換，VS Code 與終端機的對話用 `/login` 換；braid 不替你換帳號。
  在桌面 app 用某個帳號開過對話、或 CLI 登入過，就會自動出現；名稱與顏色可以改。
  其他帳號還有對話沒搬過來時，最後會有「從其他帳號搬過來」（見「遷移」）。
- **切換**、**同步**、**歸屬**：見下面各節。遷移不是分頁，是帳號頁裡的一個動作。

## 用量切換

用量快到門檻時（預設 5 小時 90%、7 天 95%），輸入框上方提醒你換成哪個帳號：

> **braid** 公司 5 小時用量 92%，16:00 重置。在桌面 app 換成「公司 2」就能接著做，對話都已同步過去。　[16:00 前別再提醒]

braid 不替你換帳號，也不開新視窗：換帳號一律由你自己來，braid 只負責提醒與同步。提醒怎麼說看這個對話在哪裡跑：

| 對話在哪裡 | 提醒怎麼說 |
|---|---|
| 桌面 app，有開同步 | 在 app 換成某某就能接著做，對話都已同步過去 |
| 桌面 app，沒開同步 | 可以在 app 換成某某，並建議在 braid 開「同步」讓對話自動跟過去；另有「打開 braid」 |
| VS Code、終端機 | 用 `/login` 換成某某就能接著做：這裡的對話紀錄本來就不分帳號，這段對話不用搬 |

建議的是切換頁「換帳號的順序」裡由上往下第一個能換、用量也還沒到門檻的帳號。桌面 app 的對話只建議在桌面 app 登入過的帳號：
只用「新增帳號」加進來的，提示會說先在桌面 app 登入它；一個都沒有時，會說在桌面 app 登入另一個帳號，braid 就會認得它。

**braid 認得哪些帳號**：在桌面 app 用某個帳號開過對話、或 CLI `/login` 過，就會自動出現。也可以在帳號頁按「新增帳號」，
會開一個視窗跑 `claude setup-token`，用瀏覽器登入要加的帳號，再把畫面上的一年期憑證貼進去。你現在登入的帳號不受影響。
`claude` 不在 PATH 上也沒關係（例如只裝了桌面 app）：braid 會改用桌面 app 自帶的那份；真的哪裡都找不到，
面板會給官方的安裝指令，不會開一個注定失敗的視窗。
存好後，腳本會用這組憑證呼叫一次「列出模型」（不算用量），從回應讀出它屬於哪個組織。
一年期憑證只查得到組織、查不到是哪個帳號，所以用組織判斷：
- 和**目前帳號同一個組織**：你在一個組織通常只有一個帳號，所以多半就是目前這個帳號（瀏覽器剛好登著它）。
  會明確警告，預設是刪掉這組憑證，請你在瀏覽器登出（或開無痕視窗）再新增；真的是同組織的另一個帳號，另外按確認才加入。
- 和**已經認得的另一個帳號同一個組織**（例如在桌面 app 登入過的個人帳號）：當成那個帳號，更新它的憑證，不會多一筆。
- 另一個組織：照查到的組織存成新帳號，你只要取個名稱。
- 查不到（例如連不上）：才請你自己選組織，並提醒你確認登入的不是目前這個帳號。

用 braid 新增過憑證的帳號，之後在桌面 app 或 CLI 登入同一個帳號（信箱相同）時，braid 會把兩筆併成一筆：
憑證、你取的名稱與顏色都接過去，不會出現兩張同一個帳號的卡片。

**不看資料夾**：提醒與建議的帳號不看資料夾，也不看「歸屬」——歸屬只管新頁用哪個帳號發布，不管對話。

**桌面 app 的對話**：app 的側欄依帳號分開，換帳號後，原本那個帳號的對話不會出現在新帳號的側欄。開「同步」的話，
對話會自動複製到另一個帳號，換過去側欄就是最新的（見「同步」）。

## 歸屬（公司與個人分開）

在「用法」打開「歸屬」。一張表決定每個資料夾歸哪個帳號（含子資料夾，多條符合取最具體的；worktree 跟著它的專案），
在那裡做的新頁（artifact）就用那個帳號發布。官方的限制是：頁面屬於發布它的對話登入的帳號，事後不能轉移，
所以 braid 在發布前就把關。

**歸屬只管新頁，不管對話**：資料夾和這個對話的帳號對不上時，對話照常、不跳警告；用量提醒建議換誰、同步帶哪些資料夾也都不看它。

| 情境 | braid 怎麼做 |
|---|---|
| 對得上（同一個帳號，或同一個組織），或這個資料夾設成「不分」 | 不打擾；新頁照常發布，記下網址 |
| 對不上時發布新頁（例如公司專案、個人帳號的對話） | 擋下，在對話裡跳出選擇框問你：**排進待發布**／用目前帳號發布（頁面就歸它，之後不能轉移）／這次不發 |
| 還沒設定的資料夾發布新頁 | 擋下，選擇框問你：**先排著，之後再決定**／歸目前帳號並發布／歸另一邊的第一個帳號、先排著／這次不發；選了歸誰就寫回表 |
| 選擇框被關掉、沒有回答，或非互動（`claude -p`） | 一律當成先排著：不發布、不改表 |
| 在選擇框的「其他」打字 | 一樣先排著，你打的字交給 Claude 照著處理；它要發布時 braid 會再問你一次 |
| 排著的頁 | 原始檔存到 `~/.claude/artifact-sources/<專案>/`，排進「待發布」；同一個專案、同一個標題再送一次只更新那一筆 |
| 在歸屬帳號（或同組織的帳號）的對話裡 | 輸入框上方列出排著等它的頁，直接按「發布」（多張時是「全部發布」），不用進面板 |
| 在還沒設定、又有頁排著的資料夾的對話裡 | 輸入框上方問這個資料夾歸誰：歸這個對話這一邊（或「不分」）就當場發布排著的頁，歸另一邊就留在待發布 |
| 更新已有的頁 | 不擋 |

**決定只算你按的選項**：選擇框是 Claude Code 自己的，Claude 沒辦法替你選，也沒有哪個指令能讓 Claude 自己放行。
第一個選項一律是「先排著」：就算你不在、選擇框被自動帶過，也不會替你發布或改表。

**braid 不替你換帳號**：想讓公司專案的對話也用公司帳號，自己在桌面 app 換過去（VS Code、終端機用 `/login`）；
兩個帳號有在同步的話，換過去對話就在。braid 不會因為歸屬對不上而提醒你換帳號，也不開新視窗接著做。

**待發布的頁**：在歸屬帳號登入的對話（例如在桌面 app 換成它），輸入框上方就有「發布」，braid 替你發布並記下網址；
也可以打開 `/braid 歸屬`，在「待發布的頁」逐張發布或丟掉。確定要歸目前帳號，按「就用某某發布…」再確認一次。
官方只保證 `/login` 的對話能發布，所以 0.10.0 以前 braid 用一年期憑證開的視窗不給「發布」，只能先排著。
清單是 `~/.claude/artifact-sources/index.json`（網址、歸屬帳號、標題、專案資料夾），用檔案存，另一個設定目錄的 Claude Code 也讀得到。

**快速設定**：歸屬頁的「依 git 遠端快速設定」掃描這個專案旁邊的資料夾，依遠端的主機／擁有者分組（不是 git repo 的工作區，
看底下 repo 最多的那個），一組選一次；沒有遠端的請逐一設定。

**第二個帳號沒有 `/login` 的對話時**（只有一年期憑證）：開一個只負責發布的終端機——
`CLAUDE_CONFIG_DIR=~/.claude-publish claude`，在裡面 `/login` 那個帳號，並在同一個設定目錄裝 braid
（`CLAUDE_CONFIG_DIR=~/.claude-publish claude plugin marketplace add MiskaWu/braid && CLAUDE_CONFIG_DIR=~/.claude-publish claude plugin install braid@braid`）。
那邊的輸入框上方與「歸屬」頁就看得到待發布的頁。`claude -p`（非互動）預設不能發布頁面，官方沒有寫開啟方式，所以這個終端機要互動式。

**還沒做**（試用後再做）：搬家（另一個帳號重發＋舊網址改轉址頁＋記憶裡的連結換新）。

## 同步

桌面 app 的側欄依帳號分開存：換帳號後，另一個帳號的對話就看不到了。同步讓兩個帳號的側欄保持一致，
一個帳號用量用完，在 app 換到另一個帳號就能接著做，不用結束 Claude、不用等。

1. 同步頁打開「同步」、選「和哪個帳號同步」。**預設同步全部資料夾**，之後新出現的資料夾也算；兩個帳號不在同一個組織時會提醒你，
   全部同步會連個人專案也帶過去。要分開的話，把範圍改成「只同步我挑的資料夾」，再一個一個加：
   一鍵加入這個對話的資料夾、從清單挑（只列還沒加的，附兩邊各有幾個對話）、或直接輸入路徑；每一列都可以移除。
2. 之後是自動的：桌面 app 開著時，braid 大約每分鐘把**app 現在登入的帳號**的對話複製到另一個帳號；
   用量快用完時再馬上同步一次。換過去時側欄就是最新的。換過去之後方向跟著反過來，兩邊一直保持一致。
3. 同步頁會顯示現在從哪個帳號複製到哪個、上次同步的時間與筆數；也可以按「現在同步」。

為什麼 app 開著也能寫：app 只把**目前登入的帳號**的清單放在記憶裡，換帳號時才從磁碟重讀新帳號的清單。
braid 只寫沒登入的那個帳號，所以不會被 app 蓋掉，也不會動到你正在用的清單。

- **刪除也跟著走**：在一邊刪掉的對話，另一邊的側欄紀錄也會刪掉。刪之前先把那筆原樣存到
  `~/braid-backups/sync-deleted/<帳號>/<組織>/`（存不進去就不刪）。刪掉之後又在另一邊用過的，那邊不刪。
  braid 只刪側欄紀錄：停程序、刪 worktree 與分支、刪對話檔，是 app 在你刪的當下做的，worktree 與分支兩個帳號共用，
  在哪一邊刪都一樣會被刪（有未提交的變更時 app 會留著）。在 WSL 跑的對話，對話檔 app 不刪，`claude --resume` 還找得到。
- **兩邊都動過同一個對話**：以最後活動時間較晚、檔案較新的那一邊為準。對話內容本身存在電腦上同一個檔，兩邊看到的是同一份。
- **已儲存的環境不自動同步**：環境存在 app 的內部資料庫，app 開著時寫不進去。要帶過去時按同步頁「已儲存的環境」的「帶過來…」，
  會開遷移工具的視窗（結束 Claude、確認信箱、輸入 Y，寫入前先備份）。

CLI 的對話本來就不分帳號（都在 `~/.claude/projects`），不需要同步。

## 遷移

換帳號後，把舊帳號在 Code 分頁的對話和已儲存的環境複製到桌面 app 現在登入的帳號。這是換帳號那一刻做一次的動作，
不是常駐的用法，所以沒有自己的分頁，入口有三個：

- **帳號頁最後的「從其他帳號搬過來」**：列出這台電腦上還有對話沒搬過來的其他帳號（各有幾個、最近一次活動），
  每個都有「試跑」與「搬過來…」。搬完就不再列；和這個帳號在同步的帳號也不列（同步會把對話帶過來，環境到同步頁按「帶過來…」）。
- **輸入框上方問一次**：在桌面 app 現在登入的帳號的對話裡，第一次遇到別的帳號有對話還沒搬過來時，問你「看看要搬什麼」（打開帳號頁）
  或「不用了」；按了任一個就不再問。VS Code 與終端機的對話紀錄本來就不分帳號，不會問。
- **直接打指令**：
  - `/braid migrate 試跑`：另外開一個視窗**只列計畫、不寫入**。Claude 不用結束，先跑這個看看。
  - `/braid migrate`：正式搬。另外開一個視窗，它會請你從系統匣（macOS 是選單列）**結束 Claude**，
    只關視窗不夠；這個對話會跟著中斷，沒關係。工具備份、搬完，會問要不要重新開啟 Claude。

帳號頁的「試跑」「搬過來…」開的是同一個視窗，只是直接指定從哪個帳號搬。

**挑要搬什麼**：視窗會跳出勾選清單，列出舊帳號的**專案資料夾**（各有幾筆對話、最近的是哪一筆）和**已儲存的環境**，
只勾要搬到新帳號的就好；勾完可以選擇再展開，逐筆挑對話。沒勾的留在原帳號，那些資料夾的預設設定也不會跟過去，
個人專案不會被帶進公司帳號。Windows 的清單用 Ctrl+A 全選、Ctrl＋點擊多選；Mac 的清單預設全選，取消不要的即可。

雙擊的方式流程相同；想只看計畫，Windows 加 `-DryRun`、macOS 加 `--dry-run`。
不想跳清單、直接指定的話：Windows `-Projects "資料夾1,資料夾2" -Presets 環境名稱`（`all` 全部、`none` 都不要、
`folders` 只帶工作資料夾在指定專案裡的環境），macOS 用 `--projects`、`--presets`。

**寫入前一定要看清楚方向**：視窗會顯示「目前登入（搬到這裡）：你的信箱」，最後問「方向對嗎」，
要輸入 Y 才會寫入（直接按 Enter 不算）。信箱不是你要搬過去的帳號（例如公司信箱），就輸入 N，
到桌面 app 換帳號後再執行。帳號頁（有備份時）與同步頁的「備份」區塊列出最近 5 份備份，按「還原…」可以還原。

## 安全

- **登入憑證不經過 Claude**：新增帳號在新開的視窗裡由腳本處理，面板與模型碰不到憑證。
  憑證存在 macOS 鑰匙圈、Windows 認證管理員、Linux 的系統鑰匙圈；沒有系統鑰匙圈的 Linux／WSL 存成只有你讀得到的檔案
  （`~/.config/braid/credentials/`，權限 600，和 Claude Code 在 Linux 存自己登入的方式相同）。
- **不繞過公司政策**：公司設定 Claude Code 只能用公司組織登入（managed settings 的 `forceLoginOrgUUID`）時，
  braid 不讓新增帳號。
- **只複製、不搬移**：遷移與同步都不動來源帳號的資料。可以重跑，已經搬過的會略過。
- **寫入前先備份**到 `~/braid-backups/<時間>/`，完成畫面與「備份」區塊（帳號頁、同步頁）都能還原。自動同步只在刪除時備份那一筆
  （`~/braid-backups/sync-deleted/`）；新增與更新是用同一段對話較新的版本，不另外備份。
- **備份不會一直長大**：帳號頁與同步頁的「備份」區塊可以選保留多久，預設同步刪掉的對話留 30 天、
  整份備份留最新 5 份（也可以選一直留著）。braid 大約每 6 小時清一次，改設定時馬上清；
  只清名稱像 `20261016-140211` 的整份備份資料夾與 `sync-deleted` 裡的檔案，其他放在 `braid-backups` 的東西不碰。
- **不需要系統管理員權限**：只讀寫自己的使用者資料夾。
- **app 開著時不寫 app 正在用的資料**：工具會等你結束 app（試跑例外，只讀不寫）；自動同步只寫沒登入的那個帳號。
- **不會搬錯方向**：顯示要搬過去的帳號信箱，要你輸入 Y 確認；app 自己記的兩份「目前帳號」說法不一致時直接停下，不猜。
- **卡住會問，不會直接停掉**：

  | 狀況 | 工具怎麼做 |
  |---|---|
  | app 還開著 | 說明怎麼結束並等你；Windows 可按 K 強制結束（會先確認），macOS 可由工具送出「結束」 |
  | 寫檔失敗（防毒掃描中、檔案被占用） | 問你：重試／略過這一項／全部取消 |
  | WSL 或遠端主機上的對話紀錄確認不到 | 問你：仍要複製嗎 |
  | 讀不了環境資料 | 問你：只搬 session，還是取消 |
  | 公司政策禁止執行 PowerShell 腳本 | 不繞過，請聯絡 IT |

## 會搬什麼（遷移與同步）

| 項目 | 處理 |
|---|---|
| Code 分頁側欄的 session | **搬**：複製到新帳號，點進去就能接著做（對話紀錄本來就在電腦上） |
| 封存狀態 | **搬**：舊帳號封存的，新帳號也是封存（自動同步之後在一邊封存或取消封存，另一邊也跟著） |
| 已儲存的環境 | **搬**（同步要按「帶過來…」）：連同各資料夾預設的模型與 effort、最近使用的位置；新帳號已有同一個資料夾的環境就保留新帳號那筆 |
| Claude Code 的記憶、`CLAUDE.md`、設定、hooks | **不用搬**：都在 `~/.claude`，依專案資料夾分，不分帳號 |
| claude.ai 的聊天、Projects、artifacts、claude.ai 記憶 | **搬不了**：存在伺服器、綁帳號 |
| Cowork 的對話與記憶、從 CLI 開的 session | 這一版還沒處理 |

**一台電腦只用一個 `~/.claude`**：不要照官方的多帳號建議替每個帳號設 `CLAUDE_CONFIG_DIR`，
那樣記憶、對話紀錄、設定會被按帳號拆開。braid 的多帳號都共用同一個 `~/.claude`。

## 平台狀態

- **Windows（含在 WSL 裡用 Claude Code）**：遷移已用真實資料重演，結果與實際狀態逐欄相同。
  憑證存取、新增帳號的腳本用 Windows 認證管理員實測過；面板與提示在終端機與桌面兩種畫面都有自動測試。
- **macOS**：遷移邏輯與 Windows 版用同一套測試資料驗證；與 macOS 系統溝通的那一層（JXA、鑰匙圈、Terminal）
  還沒在 Mac 實機跑過，第一次請先用試跑，有問題回報。
- **Linux**：用量切換可用；沒有圖形桌面時（例如 SSH），「新增帳號」會改成給你一行指令，在另一個終端機自己執行。

## 疑難

- **「找不到目前登入帳號的 session 資料夾」**：還沒用新帳號在 Code 分頁開過對話。先用新帳號登入桌面 app，
  在 Code 分頁開一個對話（打一句話就好），工具靠這個認得新帳號。
- **環境顯示「app 的環境資料格式改版了」**：桌面 app 改了資料格式，工具不猜、直接略過環境，請更新工具。
  session 仍會照常搬。
- **看到「已停用指令碼執行」**：公司政策禁止 PowerShell 腳本，請聯絡 IT。
- **「兩處紀錄對目前登入哪個帳號說法不一致」**：打開桌面 app，確認登入的是要搬過去的帳號，在 Code 分頁開一個對話，結束 app 後再跑。
- **帳號認錯、認不出來，或提示說的換帳號方式不對**：在那個對話輸入 `/braid 診斷`。它會列出 braid 版本、平台、
  這個對話的帳號是怎麼認出來的（桌面 app 給的環境變數、或讀了哪個 `.claude.json`）、該怎麼換帳號、家目錄與 `CLAUDE_CONFIG_DIR`、
  桌面 app 現在登入誰、braid 認得的帳號、用了哪些用法與同步狀態、找到的 `claude`。信箱遮掉、帳號只列 id 開頭，不含任何憑證，
  可以整段貼給幫你的人。
- **輸入 `/braid` 沒反應**：先輸入 `/reload-plugins` 或開新對話。還是沒有的話，可能是你的帳號還沒開放 mod 功能：
  在 `~/.claude/settings.json` 的 `env` 加 `"CLAUDE_CODE_ENABLE_FUNCTION_HOOKS": "1"` 後開新對話；或改用雙擊的方式遷移。
